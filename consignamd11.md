# Pre-entrega: Dashboard de Análisis de Ventas Retail

> **Estado:** No habilitada. Se habilita el 27 de octubre después de las 21:00.

## Propósito

Aplicar los principios de visualización de datos y *storytelling* para transformar un conjunto de datos crudo en una narrativa visual clara y accionable que facilite la toma de decisiones.

## Qué construir

Crear un **dashboard interactivo** utilizando una herramienta de Business Intelligence (Tableau, Power BI, Looker Studio o similar), basado en un **dataset de ventas retail**.

El dashboard debe responder a una **pregunta de negocio específica**, por ejemplo:

> «¿Qué categorías de productos están impulsando el crecimiento en el último trimestre?»

## Entregable

Enlace público a un dashboard interactivo en Tableau, Power BI o Looker Studio, con **al menos tres visualizaciones coordinadas**.

## Pasos sugeridos

1. **Definición del usuario.** Identificar quién verá el dashboard (por ejemplo, un Gerente de Ventas) y qué problema necesita resolver.
2. **Selección de visualizaciones.** Elegir al menos tres tipos de gráficos diferentes que representen mejor los datos (por ejemplo: serie temporal para tendencias, barras para comparaciones de categorías, mapas para distribución geográfica).
3. **Jerarquía visual.** Usar el tamaño, el color y la posición para guiar el ojo del usuario hacia los datos más importantes.
4. **Storytelling.** Añadir títulos descriptivos y breves anotaciones que expliquen el *porqué* de las variaciones detectadas en los datos.
5. **Publicación.** Generar un enlace público o compartido para que el tablero sea accesible.

## Criterios de evaluación

La consigna los presenta como «Respondé las siguientes preguntas»; en la práctica son los criterios con los que se revisa la entrega:

- [ ] **1. Accesibilidad del enlace.** El enlace entregado es accesible y el dashboard carga correctamente.
- [ ] **2. Variedad de gráficos.** Incluye al menos tres tipos de gráficos funcionalmente distintos y relevantes para el contexto.
- [ ] **3. Estructura de lectura.** El dashboard presenta una estructura lógica de lectura (de lo general a lo específico).
- [ ] **4. Títulos descriptivos.** Los títulos de las visualizaciones son descriptivos y no solo indican el nombre de las variables.
- [ ] **5. Paleta consistente.** Se utiliza una paleta de colores consistente que facilita la interpretación de los datos sin saturar al usuario.

## Errores comunes

- **Ruido visual.** Evitar demasiados colores o elementos decorativos que no aporten información.
- **Gráficos inadecuados.** No usar gráficos circulares (*pie charts*) para comparar más de 3 categorías.
- **Falta de contexto.** Asegurar que todos los ejes tengan etiquetas y que los valores tengan formato de moneda o porcentaje según corresponda.
